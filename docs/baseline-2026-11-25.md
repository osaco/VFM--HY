truth fixes made on top of it. It is evidence for the roadmap's Phase 0; it is not a claim that
the remaining phases are complete.

| ZIP SHA-256 | `dist/SHA256SUMS.txt` — published beside the archive, never inside it |

The ZIP digest is written to `dist/SHA256SUMS.txt` rather than into this document: this file is
copied into the archive, so embedding the archive's own hash would change the archive and
invalidate the value. `tools/package.ps1` now emits the digest automatically.

`tools/package.ps1` also builds the archive entry by entry: both `Compress-Archive` and
`ZipFile.CreateFromDirectory` store Windows path separators on PowerShell 5.1, which makes
Info-ZIP warn and exit non-zero. Entries are now written with forward slashes, so `unzip`
extracts cleanly with status 0.

The ZIP was built with `tools/package.ps1 -SkipBuild`. It contains `VFM.exe`, `libvlc.dll`,
`libvlccore.dll`, `sqlite3.dll`, the full `plugins/` tree, the docs and the licence file. The
packaged `VFM.exe` hash matches the built binary (`379c616f…`).

`tools/package.ps1` previously failed to parse under Windows PowerShell 5.1 because three
messages contained non-ASCII punctuation in a UTF-8 file without a BOM; the messages are now
ASCII. After that fix the portable bundle was produced.

One flake was found and fixed while collecting this evidence: `check_geometry` slept a fixed
4 s and took a single snapshot, while a cold start can leave the engine's size probe running
for up to 6 s before it re-arms the frame buffer. The first run against the freshly extracted
archive therefore measured a 320×628 ellipse, and the retry measured 628×628. The check now
polls until the shape settles (15 s cap, same 8 % tolerance), so it measures the settled
picture instead of a snapshot taken mid-recovery; a picture that never becomes round still
fails. Two consecutive runs after the change passed 7/7.

This proves the bundle finds `libvlc.dll`, `libvlccore.dll` and `plugins/` beside itself; it
does not yet prove install/upgrade/uninstall, file associations or a signed installer.

### Host quirk found while testing the bundle (not a product bug)

Running `dist/VFM-1.0.0/VFM.exe` **in place** failed with `Io(PermissionDenied)` while creating
its data folder. The cause is the working copy, not the code: this repository tree carries a
*low* mandatory integrity label (`Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`), so every
file created inside it inherits low integrity, and a low-integrity process may not write to a
normal user folder. `icacls dist /setintegritylevel (OI)(CI)M /T` cannot repair it from a
non-elevated shell (setting a label needs `WRITE_OWNER`), and an extracted copy at `D:\vfm-verify`
— outside the labelled tree — runs correctly, which is what the checks above use.

The failure path is now reported honestly instead of surfacing a bare `Io(Os { code: 5 })`:

```
VFM cannot write its settings file:
  D:\…\settings.toml
  Access is denied. (os error 5)

The folder is read-only, on a protected drive, or owned by another user.
Pick a writable location with --data-dir.
```

The same message covers the genuinely common cases (read-only USB stick, a folder owned by an
administrator, a redirected profile), so it is a real error-path improvement and not a
workaround for this machine.

The binary was renamed from `vfm-spike.exe` to `VFM.exe` so the shipped name matches the
product. Packaging scripts, the Inno Setup script, the verification tools and the README were
updated in the same change.

## Truth fixes in this revision

* **Track popovers use libVLC's own track descriptions.** `libvlc_audio_get_track_description`
  and `libvlc_video_get_spu_description` are now bound; each popover row keeps the real track
  id, so sparse ids select correctly and an empty engine list shows no rows. The previous
  "Audio 1 / Sub 1" labels were positional guesses.
* **Subtitle outline width is rendered.** The four outline copies use a
  `subtitle-outline-width` property fed from the cue style, instead of a fixed 2 px.
* **The default layout matches the shipped bar.** `Layout::default()` now lists the four tail
  controls the player actually draws (audio, subtitles, settings, queue). Previously a fresh
  install hid the queue and settings buttons because they were absent from the default layout.
* **Tail-button order is applied.** `Layout::trailing_slots` assigns each rendered control a
  slot measured from the right edge; reordering in the customizer moves the real buttons.
* **RTSP is a real RTSP chain.** The RTSP stream preset now emits
  `#transcode{…}:rtp{sdp=rtsp://…}` and reports an `rtsp://` viewer URL; it no longer labels an
  HTTP stream as RTSP.
* **Branding.** The placeholder VLC-style cone was replaced with an original VFM monogram
  (`assets/branding/vfm-256.png`, `vfm-512.png`, `vfm.ico`).

## Still not done

The remaining gaps are listed in `PHASES.md` and `docs/phase-11.md`. In particular: seek-thumbnail
generation, capture-device enumeration, full 20-control bar rendering, DPI 125/150/200 % and
multi-monitor screenshots, high-contrast mode, EXE icon embedding and installer signing are still
open. Rotation and flips are now applied to the rendered frame (proof in
`docs/compare/transform-id.png`, `transform-rot90.png`, `transform-fliph.png`). 4K playback was
measured (below) and is too slow on the CPU callback path; it is a known limitation, not a pass.
None of the open items is claimed as working here.

## Follow-up: the bench harness reported zero frames (fixed)

After the baseline commit, `--bench` printed 0 decoded frames while the same file played in the
window. The cause was not the engine: `absolutize()` canonicalised relative CLI paths, and
`Path::canonicalize` returns a verbatim `\\?\D:\...` path on Windows. libVLC cannot open those —
the input goes straight to `Ended` (state 6) with `time=0`, no error dialog. The GUI harness
never hit it because it always passes an absolute path.

* `absolutize()` now strips the verbatim prefix (drive paths become `D:\...`, UNC paths
  `\\server\share\...`), with unit tests for both forms.
* The bench clock starts on the first decoded frame, fps are divided by the played window
  (not the process lifetime), a bench that never starts exits with status 2 and an explicit
  message instead of printing a zeroed summary, and the summary now reports seek latency to
  the first new frame.

Fresh 25 s runs (i7-11800H, Windows 11 22631, software renderer, IDDCX display):

| Clip | Chroma | Decoded fps | Presented fps | Dropped | Avg copy | Seek | Peak WS |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1080p60 | RGBA | 35.7 / 36.3 | 35.5 / 36.0 | 0.7–0.9 % | 5.6 ms | 20–41 ms | 251 MB |
| 1080p60 | RV32 | 60.0 | 48.2 | 16.3 % | 7.6 ms | 20 ms | 251 MB |
| 4K30 | RGBA | 8.4 / 9.1 | 8.4 / 9.1 | 0 % | 25–27 ms | 72–82 ms | ~680 MB |

The CPU callback path therefore does not sustain 1080p60 (RGBA) or 4K30; RV32 decodes at the
full rate but the software present path discards a sixth of the frames. Details and the
NV12 + GPU optimisation path are in `docs/spike.md` §4. This is recorded as a limitation, not
as a pass.
